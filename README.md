# Jigas — граф переводов

Локальный аналитический прототип для AML-аналитика: помогает выбрать клиентов для следующей проверки по графу переводов и увидеть числовые основания гипотезы. Из трёх Parquet-файлов он строит направленный граф, рассчитывает роли и приоритеты, затем выпускает CSV и интерактивный отчёт. Выводы требуют проверки человеком.

## Быстрый запуск и проверка для жюри

Для текущего проверенного выпуска нужен Docker Engine с Compose v2 и интернет **на этапе сборки образа**. На Windows/macOS выполните из корня репозитория:

```text
docker compose build pipeline
docker compose run --rm prepare
docker compose run --rm pipeline
docker compose run --rm --entrypoint python pipeline test_contract.py --data /app/data --out /app/out
```

На Linux используйте [команды с UID/GID текущего пользователя](#linux-bind-mounted-каталоги), чтобы Docker мог записать в `data/` и `out/`. Если Docker недоступен, ниже есть [запуск через Python 3.13](#локальный-запуск-python). Архив организатора уже лежит в `track_data/data (1).zip`; отдельно скачивать данные для этого сценария не нужно.

После успешного запуска откройте `out/report.html` в браузере и проверьте:

1. В `out/validation.json` стоит `"status": "success"`; отчёт показывает 2 248 узлов, 3 119 направленных рёбер и 4 840 транзакций. Проверочный скрипт выше завершается с кодом 0.
2. `top_nodes.csv` содержит 20 строк топа. Возьмите полный `gid` из первой строки, найдите его в отчёте и сопоставьте роль и приоритет с `nodes_roles.csv`.
3. Откройте связи выбранного узла и одну из 89 групп в графе; стрелки показывают направление переводов. Проверьте также узел на глубине 4: отсутствие наблюдаемого выхода не означает доказанного конечного получателя.

Текущий стек: Python 3.13, pandas, NumPy, PyArrow, NetworkX, HTML/JavaScript и локальный vis-network. Сборка интерфейса на React + Vite описана ниже как следующий выпуск; команды выше относятся к проверенному автономному HTML.

> **Статус проверенного P0-контура:** на коде `aed8e63` Docker выпустил все пять артефактов; `test_contract.py` прошёл на каждом. CSV побайтно совпали между прогонами; медиана — 4,327 с, максимум — 4,642 с. Headless system Chrome открыл `file://`-отчёт с блокировкой HTTP(S): canvas vis-network отрисовался, интерактивные сценарии прошли, ошибок страницы и внешних запросов нет. ## Требования

- Docker Engine и Docker Compose v2 на Linux либо Docker Desktop с Docker Compose на Windows/macOS — рекомендуемый способ запустить проект без установки Python на хосте.
- Для локального запуска без Docker — Python 3.13.
- Стек: Python 3.13, pandas, NumPy, PyArrow и NetworkX; batch CLI без БД и API-сервера; HTML/JavaScript с локальной копией vis-network 10.1.2. Версии Python-зависимостей закреплены в `requirements.txt`.
- Официальный архив входа находится в `track_data/data (1).zip` и уже включён в репозиторий. Подготовленные Parquet хранятся в игнорируемой `data/` и не попадают в Git.

## Запуск в Docker

Из корня репозитория соберите образ:

```powershell
docker compose build pipeline
```

На Windows/macOS затем выполните команды по порядку:

```powershell
docker compose run --rm prepare
docker compose run --rm pipeline
```

Сервис `prepare` извлекает три Parquet из архива в локальную папку `data/`; сервис `pipeline` читает её только для чтения и записывает выпуск в `out/`. Образы нужно собрать при наличии доступа к пакетам Python. После сборки само приложение не требует внешних API, ключей, GPU или передачи входных файлов наружу; фактический запуск с отключённой сетью будет зафиксирован в [протоколе проверки](docs/validation.md).

Проверить контракт на выпущенных файлах можно в контейнере:

```powershell
docker compose run --rm --entrypoint python pipeline test_contract.py --data /app/data --out /app/out
```

### Linux: bind-mounted каталоги

Образ запускает приложение от UID 10001. Чтобы `prepare` и pipeline могли записывать в локальные bind mounts на обычном Linux, создайте `data/` и `out/` от имени текущего пользователя и запускайте сервисы с его UID/GID:

```bash
mkdir -p data out
docker compose build pipeline
docker compose run --rm --user "$(id -u):$(id -g)" prepare
docker compose run --rm --user "$(id -u):$(id -g)" pipeline --data /app/data --out /app/out
docker compose run --rm --user "$(id -u):$(id -g)" --entrypoint python pipeline test_contract.py --data /app/data --out /app/out
```

Если каталоги уже существуют, у текущего пользователя должны быть права записи. Этот Linux clean-clone путь пока не проверялся на Linux-хосте.

## Результаты запуска

Проверенный pipeline создаёт в `out/`:

- `nodes_roles.csv` — по одной строке на каждый узел, роль, поддержка гипотезы, кластер, приоритет и числовое объяснение;
- `clusters.csv` — размер и число seed в кластере, внутренний оборот в KZT, список ключевых узлов и осторожная гипотеза;
- `top_nodes.csv` — первые 20 узлов по неокруглённому приоритету с детерминированным порядком равных значений;
- `report.html` — автономный локальный отчёт с поиском, карточкой узла и графом;
- `validation.json` — версия среды, хеши входов, параметры и итоговые проверки выпуска.

CSV используют полные десятичные `gid`, суммы кластеров содержат две цифры после точки. В HTML идентификаторы передаются строками, чтобы браузер не округлял большие числа. `role_score` и `priority_score` — поддержка структурной гипотезы, а не вероятность преступления.

Откройте `out/report.html` двойным щелчком в браузере. В отчёте можно искать полный `gid`, изучать направленные связи и ограничения наблюдения; таблицы CSV можно открыть отдельно.

Отчёт встраивает локальные JS/CSS vis-network; ссылки на CDN не используются. Библиотека указана как `Apache-2.0 OR MIT`; файл лицензии лежит в [assets/vis-network.LICENSE.txt](assets/vis-network.LICENSE.txt). Если распространяете автономный HTML отдельно от репозитория, приложите этот файл лицензии.

## Как читать выводы

Граф ограничен исходящей выборкой до четырёх шагов от seed и июлем 2026 года. Нулевой исходящий поток на depth=4 означает границу наблюдения, а не доказанный конечный перевод. Кластер, достижимость от seed, сумма или роль сами по себе не показывают владельца денег и не устанавливают нарушение. Ground truth для оценки точности гипотез не предоставлен.

## Правила ролей и приоритет

Основная роль выбирается по порядку таблицы; все совпавшие правила сохраняются как вторичные. S — число различных seed, достигающих узла за 1–4 направленных шага в месячном графе; B — направленная невзвешенная betweenness. Q90 вычисляется по положительным B всего входа, D — дни от последнего входа до 31.07.2026.

| Роль | Условие |
|---|---|
| coordinator | S≥2, входящих и исходящих соседей ≥2, B>0 и B≥Q90(B>0) |
| distributor | ≥10 различных получателей |
| consolidator | ≥3 различных плательщиков |
| transit | Не seed, depth<4, положительные вход/выход, отношение выхода к входу 0.8–1.2 |
| terminal | Не seed, depth<4, вход>0, исходящих соседей 0, D≥2 |
| peripheral | Ни одно из правил выше не совпало |

Поддержка правила `cap*(0.5+0.5*u)` по [SPEC §4](docs/SPEC.md#4-роли-и-поддержка) не является вероятностью. Приоритет `P=0.35M+0.30A+0.20C+0.15H`: M — максимальная поддержка любого совпавшего правила, A — логарифмически нормированный наблюдаемый объём в KZT, C — нормированная достижимость от seed, H — нормированная betweenness. Полные определения/пороги — [SPEC §5](docs/SPEC.md#5-приоритет-и-объяснение). При равном P порядок задаёт точный числовой gid. Формулы эвристические; без разметки AML-точность не измерена.

Принятая вторая волна: HA-17 улучшает причины правил и читаемость уже рассчитанных фактов. P1 идёт в порядке дневные профили → запрос данных/frontier → маршруты с датами → обзор сообществ/SCC. Реализованные необязательные блоки фиксируются в parameters отчёта; отсутствующие данные не считаются нулём. Маршрут с датами не доказывает движение одних и тех же денег, а одинаковые даты не устанавливают внутридневной порядок. Перед сдачей README должен перечислить фактически включённые блоки по проверенному SHA.

## Масштабирование до примерно миллиона узлов

Это план развития, замеров такого объёма нет. Сохранить Parquet и агрегирование в целых тиынах; читать и агрегировать частями. Точную betweenness заменить ограниченной выборкой источников с опубликованными параметрами и проверкой влияния на ранжирование. Ограничивать seed-обходы по шагам, оценивать их стоимость по числу seed и рёбер. Не передавать весь граф в один HTML: выдавать обзор сообществ и выбранную окрестность с таблицами и точными ID. Хранилище/сервер добавлять после замеров объёма и сценария доступа; текущий автономный отчёт рассчитан на предоставленный набор. Обоснование и источники — [исследование, §6](docs/SECOND_WAVE_RESEARCH.md#6-what-the-external-research-adds).
