# Jigas — граф денежных переводов

[Посмотреть вживую](https://8080-sffvn5xhk.gobrev.dev)

Jigas помогает AML-аналитику разобраться в сети переводов: среди 2 248 клиентов найти тех, кого стоит проверить первыми, увидеть их связи и понять основания приоритета. Вход — обезличенная выгрузка от 81 ранее известного клиента; результат — проверяемые гипотезы о ролях и структуре сети, а не вывод о виновности.

## Что делает решение

1. Проверяет три Parquet-файла — клиентов, агрегированные направленные связи и отдельные переводы — и строит граф, сохраняя точные `gid` и денежные суммы в тиынах.
2. Считает входящие и исходящие связи, суммы, достижимость от известных клиентов и центральность. По явным порогам назначает каждому узлу одну основную роль и сохраняет все другие совпавшие правила.
3. Ранжирует клиентов по силе признаков, объёму и положению в сети; Louvain группирует связанные узлы, включая отдельные изоляты. Python выпускает три CSV и `report.json` из одного расчёта.
4. React-отчёт показывает топ-20, причины выбора, кластеры и направленный граф. Поиск работает по полному ID; интерфейс отображает рассчитанные данные и не меняет роли или приоритет.

## Чем полезен аналитику

- **Понятный следующий объект проверки:** у топа есть числовые основания, у связанной группы — первый клиент для изучения; в отчёте можно проверить направления, суммы и число переводов по его связям.
- **Объяснимость:** правила и пороги открыты, карточка показывает совпавшие роли и равные значения приоритета, включая узлы за пределами топ-20.
- **Осторожность с неполными данными:** узел на четвёртом шаге не объявляется конечным получателем лишь из-за обрыва выгрузки; неполнота входа известных клиентов отмечается отдельно.
- **Быстро и воспроизводимо:** расчёт и просмотр работают локально. Пять запусков готового образа дали одинаковые CSV, прошли контрактную проверку и заняли не более 5,656 с каждый; условия измерений — в [протоколе](docs/validation.md).

## Запуск

Нужны Docker Engine и Docker Compose v2. Из корня репозитория:

```sh
docker compose build pipeline
docker compose run --rm prepare
docker compose run --rm pipeline
docker compose up viewer
```

Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/) — дашборд откроется сразу; `/report.html` ведёт к тому же отчёту. Команда `prepare` извлекает Parquet из `track_data/data (1).zip`; один запуск `pipeline` создаёт отчёт в `out/`. Сборка требует интернета для зависимостей, готовый образ работает без внешних сервисов. Версии пакетов закреплены в `frontend/package-lock.json` и `requirements.txt`.

Проверка готового выпуска:

```sh
docker compose run --rm --entrypoint python pipeline test_contract.py --data /app/data --out /app/out
```

Пять запусков официального набора и проверка браузера описаны в [протоколе](docs/validation.md). Linux-запуск с bind mounts от UID/GID пользователя на отдельном хосте пока не проверен.

## Результат и работа с ним

`pipeline` создаёт в `out/`:

| Файл | Содержание |
| --- | --- |
| `nodes_roles.csv` | Все 2 248 клиентов: роль, `role_score`, кластер, приоритет и объяснение до 200 символов |
| `clusters.csv` | Размер, seed, внутренний оборот, ключевые узлы и гипотеза по каждому кластеру |
| `top_nodes.csv` | 20 клиентов с наивысшим приоритетом и обоснованием |
| `report.json`, `index.html`, `report.html`, `assets/` | Данные и локальный React-интерфейс с направленным графом |
| `validation.json` | Статус выпуска и хеши файлов |

В интерфейсе выберите клиента из топа или найдите его по полному `gid`. Карточка показывает основания основной и других совпавших ролей; граф — направления и суммы связей. Можно переключить окрестность на полный граф, отфильтровать роли и кластеры, открыть гипотезу группы и скачать CSV. Идентификаторы сохраняются точно, без округления в браузере. [Сценарий пятиминутного демо](docs/DEMO.md) показывает разбор конкретных узлов.

`out/` игнорируется Git: CSV воспроизводятся командами выше.

## Роли и приоритет

`in_deg` и `out_deg` — число наблюдаемых плательщиков и получателей; `S` — число seed, достигающих узла за 1–4 направленных шага; `B` — нормированная betweenness; `r` — отношение исходящей суммы к входящей; `D` — дни после последнего наблюдаемого входящего перевода. `Q90(B>0)` — 90-й процентиль положительных `B`.

| Роль | Условие | `u` | `cap` |
| --- | --- | --- | ---: |
| coordinator | `S≥2`, `in_deg≥2`, `out_deg≥2`, `B>0`, `B≥Q90(B>0)` | `min(1,S/4)` | 0,60 |
| distributor | `out_deg≥10` | `min(1,out_deg/20)` | 0,90 |
| consolidator | `in_deg≥3` | `min(1,in_deg/6)` | 0,90 |
| transit | Не seed, `depth<4`, суммы входа и выхода положительны, `0,8≤r≤1,2` | `max(0,1−abs(r−1)/0,2)` | 0,65 |
| terminal | Не seed, `depth<4`, вход положителен, `out_deg=0`, `D≥2` | `min(1,D/7)` | 0,50 |
| peripheral | Ни одно правило не совпало | — | 0 |

Для совпавшей роли `support=cap×(0,5+0,5×u)`. Основная роль — первая по порядку таблицы; её support становится `role_score`. Все совпавшие роли остаются в отчёте.

Приоритет `P=0,35M+0,30A+0,20C+0,15H`:

| Компонент | Расчёт |
| --- | --- |
| `M` | Максимальный support совпавших ролей |
| `A` | `min(1,log1p(V)/log1p(Q95(V>0)))`, где `V=(in_tiyn+out_tiyn)/100` KZT |
| `C` | `min(1,S/5)` |
| `H` | `min(1,B/Q95(B>0))` |

Квантили считаются по положительным значениям; если их нет, соответствующий компонент равен нулю. Топ сортируется по неокруглённому `P`, при равенстве — по числовому `gid`. Кластеры строятся Louvain, изоляты образуют отдельные группы. Подробные определения — в [спецификации](docs/SPEC.md).

## Границы результата

Данные охватывают июль 2026 года, внутрибанковские исходящие переводы от 81 seed, не дальше четырёх шагов и не меньше 5 000 KZT. Нулевой выход узла на четвёртом шаге может быть следствием границы выгрузки; вход seed тоже неполон. Роли и кластеры — гипотезы по наблюдаемому фрагменту, `role_score` и `P` не являются вероятностью нарушения. Размеченных истинных ролей нет, поэтому AML accuracy не заявляется.

При росте до ~1 млн узлов потребуются порционная обработка, компактное хранение графа, приближённая betweenness и загрузка в браузер только выбранной окрестности. Это [план развития](docs/ARCHITECTURE.md), производительность такого масштаба не проверялась.
