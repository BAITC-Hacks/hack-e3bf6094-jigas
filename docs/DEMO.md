# Пятиминутное демо

> **Статус: сценарий готов к репетиции; пользовательский headed review ещё идёт.** На `aed8e63` пять Docker-выпусков прошли `test_contract.py`, а headless system Chrome открыл финальный `file://`-отчёт с блокировкой HTTP(S): canvas виден, поиск/фильтры/клик/клавиатурное действие/копирование прошли, ошибок и внешних запросов нет. Медиана пяти прогонов — 4,327 с, максимум — 4,642 с. Не показывать учебный `report.example.json` или файлы от предыдущего запуска как результат текущего прогона.

## До показа

- Установить Docker Engine и Compose v2; для этого сценария выделить Docker до 12 CPU. Linux и Docker Desktop подходят.
- Заранее собрать образ и проверить доступность raw-архива:

  ```powershell
  docker compose build pipeline
  ```

- Во время демо извлечь Parquet непосредственно из архива организатора командой `docker compose run --rm prepare`.
- До показа открыть свежий `out/demo/report.html` в headed-браузере и завершить пользовательский просмотр визуального отображения, поиска, фильтра, карточки и кластера. Автоматический headless smoke пройден, пользовательский просмотр пока открыт.
- Попросить проверяющего назвать существующий `gid` во время показа. Не подставлять выдуманный ID; если введённый ID отсутствует, показать явное состояние «не найден».

## План на 5 минут

| Время | Действие и что показать |
|---|---|
| 0:00–0:20 | Показать исходный архив `track_data/data (1).zip`, запустить `docker compose run --rm prepare` и показать три созданных Parquet в `data/`. Это подготовка raw; сборка образа выполняется до демо. |
| 0:20–3:25 | Запустить таймер сразу перед расчётом, выполнить `docker compose run --rm pipeline --data /app/data --out /app/out/demo`, записать exit code и фактическое время. Проверить, что свежий `out/demo/` содержит все пять файлов: три CSV, `report.html`, `validation.json`. Не трактовать наличие старого файла как успех. |
| 3:25–3:55 | Открыть `out/demo/top_nodes.csv` или топ в свежем `report.html`. Разобрать фактические числа/пороги основной и вторичной роли, ведущие причины приоритета; при равных P пояснить порядок gid. Пояснить, что score поддерживает структурную гипотезу, а не вероятность нарушения. |
| 3:55–4:25 | В HTML открыть реальный узел depth=4 с крупным входом. Показать исходящие связи/их отсутствие и ограничение наблюдения: нулевой выход на границе не доказывает, что перевод был конечным. Сверить признаки/предупреждения; при готовом HA-14 показать конкретный запрос данных и frontier вне top-20. |
| 4:25–4:45 | Ввести `gid`, названный проверяющим, целиком. Показать карточку и направленные связи; сверить точную строку ID с CSV. Если проверяющий назвал несуществующий ID, показать явное состояние «не найден», не оставляя предыдущую карточку. |
| 4:45–5:00 | Показать выбранный кластер и его сводку, затем `clusters.csv` и ссылки/файлы трёх CSV из этого же запуска. Завершить фактически измеренным временем и статусом проверок. |

Таймер запускается **после подготовки Parquet**: целевой порог `<300 секунд` в SPEC относится к выпуску CSV, а не к сборке образа или распаковке архива. План показа оставляет примерно три минуты на расчёт. На финальных пяти Docker-запусках медиана составила 4,327 с, максимум — 4,642 с; повторите таймер на демо и называйте время именно текущего запуска. Если расчёт возвращает ошибку, не переключайтесь на прошлый выпуск.

Пример замера в PowerShell:

```powershell
$timer = [System.Diagnostics.Stopwatch]::StartNew()
docker compose run --rm pipeline --data /app/data --out /app/out/demo
$exitCode = $LASTEXITCODE
$timer.Stop()
"exit={0}; elapsed={1:N1} s" -f $exitCode, $timer.Elapsed.TotalSeconds
```

## Включённые дополнения

Общий лимит остаётся **5 минут**. После репетиции перераспределить свободное время внутри него, сохранив raw→выходы, 2–3 клиента, произвольный поиск и CSV. Показывать только реализованные и проверенные блоки, используя тех же клиентов:

- HA-11 — дневные наблюдения; HA-14 — основание следующего запроса данных.
- HA-16 — короткий маршрут с датами/суммами либо честное отсутствие маршрута. Сопоставить с месячным S, назвать неизвестный порядок same-day и отсутствие доказательства пересылки тех же денег.
- HA-13 — обзор сообщества/SCC, если он включён и помещается в сценарий; не называть SCC доказанным круговым движением денег.

Перечень показанных HA-17/P1, фактическое время репетиции и SHA добавить в блок фактов выше. Новая формула скоринга, удаление узлов и runtime-ассистент в принятую демонстрацию не входят.

После приёмки HA-15 показывать тот же выпуск через `http://127.0.0.1:8000/report.html`, включая report.json/assets. Старые file://-факты выше остаются результатом baseline; фактические команды/путь viewer, SHA и повторную репетицию фиксирует HA-10.1. Если миграция не принята, капитан явно фиксирует проверенный резервный SHA.
