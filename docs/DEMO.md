# Пятиминутное демо HackAlem AI

## Кандидат и проверенный состав

Сценарий запускается из текущего `main` и создаёт свежий выпуск в `out/`. Артефакт `out/release-current-lic/` относится к прежней локальной проверке `c9178c5` и в чистом клоне отсутствует.

В текущий кандидат входят React/Vite/Cytoscape.js, Python batch, HA-17/18, дневные профили HA-11, запросы продолжения HA-14, датированные маршруты HA-16 и обзор межкластерных потоков/SCC HA-13.

На официальной выборке: 1–31 июля 2026 года, операции от 5 000 KZT и до четырёх шагов от известных seed. В финальном выпуске 2 248 узлов, 3 119 направленных рёбер, 4 840 транзакций, 81 seed, 89 кластеров и 19 изолятов. Это структура переданной выборки, не полный граф банка.

## Подготовка до аудитории

Команды выполняются из корня репозитория. Образ собрать заранее, так как загрузка базовых образов и зависимостей требует сети. После успешной сборки выполнить обязательный Docker cleanup; он сохраняет контейнеры и volumes.

```powershell
$env:HACKALEM_IMAGE = 'jigas-graph-money:local'
$env:HACKALEM_CPUS = '12'
docker compose build pipeline
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "G:\Tools\DockerCleanup\Docker-Cleanup.ps1" -Automatic
docker compose up -d viewer
```

Заранее убедиться, что официальный архив `track_data/data (1).zip` на месте, порт `127.0.0.1:8000` свободен, а viewer запущен. Не открывать страницу через `file://`: React загружает соседний `report.json` с same-origin localhost.

## Команды свежего выпуска

В начале показа запустить подготовку входных Parquet, затем batch на официальном архиве. Сборка образа остаётся за пределами таймера выступления.

```powershell
docker compose run --rm prepare

$timer = [System.Diagnostics.Stopwatch]::StartNew()
docker compose run --rm pipeline
$pipelineExit = $LASTEXITCODE
$timer.Stop()
"pipeline exit={0}; elapsed={1:N3} s" -f $pipelineExit, $timer.Elapsed.TotalSeconds
```

`prepare` создаёт `nodes.parquet`, `edges.parquet` и `transactions.parquet`. Успешный pipeline создаёт три CSV, `report.json`, одинаковые `index.html` и `report.html`, `validation.json` и локальные JS/CSS/favicon/license в `assets/`. После него открыть `http://127.0.0.1:8000/`.

Для проверки перед выступлением сначала создать свежий выпуск тем же pipeline, затем выполнить контрактную проверку. Она не входит в пятиминутный показ:

```powershell
docker compose run --rm --entrypoint python pipeline test_contract.py --data /app/data --out /app/out
```

Пять замеров готового Docker image из [протокола проверки](validation.md): 4,508 / 4,619 / 5,656 / 5,621 / 4,454 с; медиана 4,619 с, максимум 5,656 с при лимите 12 CPU. Они включают запуск контейнера с pipeline, но исключают `prepare`, сборку образа, работу браузера и речь. Это batch timing, не длительность демо.

Сборка образа и запуск viewer сделаны заранее; вычисление нового отчёта входит в эти пять минут. PowerShell-переменная `$timer` в блоке команд выше измеряет только pipeline после `prepare`.

## Репетиция ответа на три произвольных GID

Отдельно от основного сценария потренируйте вопрос жюри: за минуту объяснить роль трёх названных узлов по метрикам. Примеры ниже можно найти в свежем `out/report.json`; на защите жюри может выбрать другие ID. Три CSV текущего выпуска побайтно совпадают с проверенным `a086162`.

- `100000000018102100` — `peripheral`, `role_score=0`: depth=4, одно входящее ребро на 7 000 KZT, исходящих рёбер и суммы нет. В этом срезе виден узел на границе наблюдения.
- `100000000031787100` — `transit`, `role_score=0.65`: depth=2, входящая и исходящая суммы по 90 000 KZT, `r=1`. Равный наблюдаемый поток согласуется с транзитной ролью.
- `100000000041368100` — `terminal`, `role_score=0.5`: depth=1, входящая сумма 160 000 KZT, `out_deg=0`, прошло 9 дней после последнего входа. В наблюдаемом периоде исходящих рёбер нет.

Это учебные примеры, а не подсказка о выборе жюри; роли описывают только наблюдения в архиве. Тренируйте этот разбор отдельно; если жюри назовёт три произвольных GID, объясните их роли по метрикам не более чем за минуту, сохранив общий лимит демонстрации в 5 минут за счёт сокращения подготовленных пояснений.

## Проверенные факты и честные ограничения

- ID `100000003684369100` — первая строка `top_nodes.csv`: coordinator, роль 0.600, приоритет 0.965, кластер 2; число также найдено поиском в `report.json` и показано в React-карточке.
- Кластер 2: 138 узлов, 3 seed, 152 внутренних ребра, `sum_kzt_internal=18838290.00`. Гипотеза HA-18 опирается на проверяемые поля лидера и группы и формулируется как описание наблюдений.
- Граничный пример `100000000018102100`: depth=4, одно входящее ребро на 7 000 KZT, ноль наблюдаемых исходящих. Не экстраполировать за пределы архива.
- Лимиты входа: только выбранный период, порог суммы и четыре шага; неполный вход seed и нулевой исходящий поток на frontier не устанавливают конечное назначение денег.
- Для продукта не заявлены AML accuracy/precision/recall и масштабирование до миллиона узлов: размеченного ground truth для этих выводов нет.
- Включены HA-11/13/14/16/17/18. На официальном входе крупнейшая SCC: 85 узлов, 242 внутренних ребра и 642 уникальных внешних получателя; вход на frontier — 56 672 164,68 KZT (15,49%). Это факты о наблюдаемой структуре, не AML-классификация. Датированный маршрут означает совместимый порядок переводов, а не прослеженный объём денег.
- GitHub push публикует код, но не отправляет заявку. Подачу подтверждает статус на платформе после нажатия «Сдать решение».
