# Пятиминутное демо

> **Статус: черновой сценарий.** На текущей ветке ещё нет подтверждённого полного запуска после интеграции HA-07.1 и ручной приёмки в браузере. Тайминги ниже — план показа, не результаты замера. Не показывать учебный `report.example.json` или файлы от предыдущего запуска как результат этого прогона.

## До показа

- Установить Docker Engine и Compose v2; для этого сценария выделить Docker до 12 CPU. Linux и Docker Desktop подходят.
- Заранее собрать образ и проверить доступность raw-архива:

  ```powershell
  docker compose build pipeline
  ```

- Подготовить каталог `out/` для нового выпуска. Во время демо извлечь Parquet непосредственно из архива организатора командой `docker compose run --rm prepare`.
- После успешной интеграции проверить, что приложение, HTML и локальные ресурсы готовы. Сейчас это ещё не подтверждено.
- Попросить проверяющего назвать существующий `gid` во время показа. Для проверки границы заранее найти по текущему выпуску реальный узел с `depth=4`, нулевой исходящей степенью и заметным входящим объёмом; не подставлять выдуманный ID.

## План на 5 минут

| Время | Действие и что показать |
|---|---|
| 0:00–0:20 | Показать исходный архив `track_data/data (1).zip`, запустить `docker compose run --rm prepare` и показать три созданных Parquet в `data/`. Это подготовка raw; сборка образа выполняется до демо. |
| 0:20–3:25 | Запустить таймер сразу перед расчётом, выполнить `docker compose run --rm pipeline`, записать exit code и фактическое время. Проверить, что запуск успешен и текущий `out/` содержит все пять файлов: три CSV, `report.html`, `validation.json`. Не трактовать наличие старого файла как успех. |
| 3:25–3:55 | Открыть `out/top_nodes.csv` или топ в свежем `report.html`. Разобрать верхнюю строку по роли, приоритету и причине. Пояснить, что score поддерживает структурную гипотезу, а не вероятность нарушения. |
| 3:55–4:25 | В HTML найти выбранный реальный узел depth=4 с крупным входом. Показать исходящие связи/их отсутствие и ограничение наблюдения: нулевой выход на границе не доказывает, что перевод был конечным. Сверить объяснение с признаками и предупреждениями отчёта. |
| 4:25–4:45 | Ввести `gid`, названный проверяющим, целиком. Показать карточку и направленные связи; сверить точную строку ID с CSV. Если проверяющий назвал несуществующий ID, показать явное состояние «не найден», не оставляя предыдущую карточку. |
| 4:45–5:00 | Показать выбранный кластер и его сводку, затем `clusters.csv` и ссылки/файлы трёх CSV из этого же запуска. Завершить фактически измеренным временем и статусом проверок. |

Таймер запускается **после подготовки Parquet**: целевой порог `<300 секунд` в SPEC относится к выпуску CSV, а не к сборке образа или распаковке архива. План показа оставляет примерно три минуты на расчёт. Если расчёт выходит за отведённое время или возвращает ошибку, назвать фактический результат и не переключаться на прошлый выпуск. Пятизапусковый замер, медиана и максимум — отдельная приёмка, этот показ их не заменяет.

Пример замера в PowerShell:

```powershell
$timer = [System.Diagnostics.Stopwatch]::StartNew()
docker compose run --rm pipeline
$exitCode = $LASTEXITCODE
$timer.Stop()
"exit={0}; elapsed={1:N1} s" -f $exitCode, $timer.Elapsed.TotalSeconds
```

## Факты для заполнения после интеграции

- SHA показанного кода: **не зафиксирован**.
- Exit code и длительность свежего запуска: **не измерены**.
- Автоматический контракт и содержимое `validation.json`: **не проверены после интеграции**.
- Проверенный `gid` верхней строки и объяснение: **заполнить по текущему выпуску**.
- Реальный пример depth=4 и его входящие показатели: **заполнить по текущему выпуску**.
- `gid` проверяющего, результат точного поиска и карточка: **проверить в браузере**.
- Кластер и соответствие трёх CSV текущему запуску: **не проверены**.
- Полный запуск без сети и пять замеров производительности: **не выполнены**.
