## 4. Что пакет упустил

1. **Контракт уже изменился.** SPEC 1.4 принят, но в проверенном main ещё нет React и `matched_roles.reason`. Наличие текста в спецификации нельзя считать завершением HA-15/17. Старые file://-проверки не подтверждают будущий localhost/report.json-выпуск.
2. **Основная роль не равна всем признакам узла.** Весь top-20 удовлетворяет consolidator. M в приоритете может браться из этого вторичного правила, даже когда основная роль coordinator. Это нужно явно объяснять в why и карточке.
3. **Ties пересекают границу CSV.** На уровне P=0,8450000000000001 находятся три узла, в CSV входит один. Принятый UI должен открывать все три, сохраняя официальный top-20 и точность длинных ID.
4. **947 terminal не имеют одинаковый score.** Score=0,5 у **803**, остальные ниже. Ни 0,5, ни cap=0,6 для coordinator не являются калиброванными вероятностями. Для terminal нужно также избегать обещания известного остатка: видны лишь отобранные переводы.
5. **43 coordinator не доказывают избыточность.** Это 1,91% узлов; B>0 у 599, порог Q90 пропускает 60 до остальных условий. Без размеченных ролей нельзя вывести «правильное» количество или менять порог ради более красивого распределения.
6. **Читаемость рёбер — уже найденная проблема.** Во второй волне все 3 119 рёбер достигали одинаковой максимальной толщины. Исправление общей шкалы входит в HA-17.2 и полезнее добавления ещё одного списка лидеров.
7. **HA-14 не полностью независима от HA-11.** Условие запроса внутридневных меток использует дневные профили. Нельзя объявить её отдельной дешёвой работой, исключив уже подготовленный слой наблюдаемых признаков и проверку JSON/UI.
8. **Время в предложенном плане не сходится.** Пять оценок из раздела 6 пакета в сумме дают **115–145 минут**, ещё без финальной установки, браузера, демо и сдачи. Последовательное выполнение всего плана не помещается в заявленные два часа.

Ссылка на SPEC вместо таблицы в README больше не является спорным местом: таблица уже добавлена. Объяснение в UI полезно, но `evidence`/`why` остаются самостоятельными выходами и должны быть понятны при чтении CSV. Приёмка трёх произвольных gid за минуту должна проверять фактические правила, включая конфликт основной/вторичной роли и границу, а не только подготовленные примеры.

## 5. Предложение по объединению и очередности

### Обязательная работа по существующим задачам

1. **HA-17.1:** завершить причины правил и факты в evidence/why. Приёмка сохраняет все роли/support/P/ranks и проверяет смысл/длину текста; изменения CSV-хешей из-за текста ожидаемы.
2. **HA-15 + HA-17.2:** завершить уже начатую миграцию и принятые средства чтения результата. Проверить на реальном report.json поиск, граф, вторичные совпадения, ties и общую шкалу рёбер. Тесты относятся к выбранному кандидату, а не к прежнему HTML.
3. **HA-09.1:** сохранить уже добавленные правила/масштабирование, синхронизировать команды с принятым viewer, добавить короткую CLI-заметку; перечислить подтверждённые инструменты разработки без догадок.
4. **HA-08.2 / HA-10:** чистый запуск по README, offline-просмотр, обязательные CSV, повторяемость, три произвольных gid, демо и финальный SHA. Зафиксировать состав до финальной приёмки; новые измерения должны относиться к нему.

### Небольшие новые дополнения

- **C5:** главный для проверки узел в тексте кластера — полезный новый кандидат. Переиспользовать top_gids и существующие признаки; новая метрика/зависимость не нужна. Принимать только с проверкой до freeze и повторной сверкой затронутого CSV.
- **C9:** датированное уточнение исследовательской ссылки на АФМ. Это исправляет недостаток источников первого сравнения; не требует юридических меток в продукте.

### Отложить

- Terminal-gate по P75/числу плательщиков; turnover tie-break; смену весов/порогов для получения желаемого распределения ролей.
- Отдельную таблицу лидеров, если принятый фильтр уже отвечает на тот же вопрос.
- Новые P1-пары, если к freeze **16:30** нет времени закончить и проверить расчёт вместе с UI. Подготовленный HA-11 backend можно интегрировать по существующему handoff; наличие backend само по себе не завершает пару. HA-14/16/13 остаются принятым развитием, но не должны задерживать обязательный выпуск.

Вместо дублирующих карточек C1/C4 следует сверять с HA-17, C2/C7 — с HA-09/08. По C5 нужно отдельное короткое решение о включении в кандидата; этот review не назначает занятому исполнителю дополнительную работу и не меняет статусы Trello.
