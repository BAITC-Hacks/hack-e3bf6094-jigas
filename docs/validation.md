# Протокол проверки

**Текущий статус: черновик.** HA-08.1 и HA-09.1 можно подготовить по контракту до интеграции. Этот документ не подтверждает приёмку; результат `test_contract.py` на актуальном выпуске и фактические ручные проверки будут добавлены после HA-07.1.

## Подготовка и запуск

Рекомендуемый Docker-сценарий из корня репозитория:

```powershell
docker compose build pipeline
docker compose run --rm prepare
docker compose run --rm pipeline
docker compose run --rm --entrypoint python pipeline test_contract.py --data /app/data --out /app/out
```

`prepare` извлекает вход из архива организатора в локальный `data/`; `pipeline` формирует текущий каталог `out/`; последняя команда запускает контрактные проверки в собранной среде. Для локального Python см. команды в [README](../README.md).

После интеграции записать сюда Git SHA и фактический результат каждой команды. Пока интеграция не готова, команды запуска и проверки являются ожидаемым интерфейсом.

## Автоматические контрактные проверки

`test_contract.py` — один скрипт на стандартной библиотеке Python, pandas и NetworkX; отдельный тестовый фреймворк не используется. Он проверяет:

- невалидный endpoint, неположительную сумму и нулевое число переводов;
- большой `gid` больше `2^53`, без округления в графе, отчёте и CSV;
- включение изолята и глубинной границы, встречные рёбра и цикл BFS;
- достижимость от разных seed, направленную нормированную невзвешенную betweenness и календарные даты;
- порядок конфликтующих ролей, исключение seed и узлов depth=4 из transit/terminal;
- формулы поддержки роли и приоритета, конечные score и числовые основания;
- обязательные столбцы и порядок, точные множества `gid`, rank, связи таблиц, кластеры и внутренние суммы;
- наличие HTML/validation JSON, остаточные маркеры шаблона и удалённые ссылки в HTML.

Ожидаемая команда после выпуска:

```powershell
python test_contract.py --data ./data --out ./out
```

Синтаксис файла проверен командой `python -m py_compile test_contract.py`; **сам тестовый сценарий и проверки текущего выпуска ещё не принимались**. На финальной сборке запустить полный скрипт и записать его exit code, SHA и сообщение результата. Затем в копиях выпуска намеренно испортить обязательную колонку, `gid`, `rank` и сумму; зафиксировать, что контрактная проверка завершается ненулевым кодом. Raw-строки и транзакции в отчёт проверки не копировать.

## Ручная проверка отчёта

После успешного выпуска отдельно проверить в браузере:

1. Открытие `out/report.html` напрямую через `file://`, без сервера и доступа к сети.
2. Поиск полного `gid`, включая идентификатор больше `2^53`, неизвестный ID и узел, скрытый фильтром.
3. Карточку изолята, depth=4 и узла со встречными направленными рёбрами.
4. Совпадение выбранной строки top-20, роли и приоритета с `nodes_roles.csv`.
5. Пустой результат фильтра, доступность клавиатурных действий, легенду и сообщения об ограничениях наблюдения.

Ручные проверки не объявлять пройденными на основании наличия HTML. Указать браузер/версию, путь или SHA выпуска и фактические наблюдения.

## Полные запуски и производительность

До сдачи выполнить пять полных запусков от исходных Parquet в свежие каталоги выпуска. Для замеров на ПК команды выделить Docker Desktop 12 CPU и записать доступную контейнеру память. Зафиксировать для каждого SHA кода, длительность, exit code и наличие пяти обязательных файлов. Сравнить хеши трёх CSV между семантически одинаковыми запусками; динамические времена в сравнение не включать. Указать CPU/RAM Docker-среды, median и maximum. Целевое время `<300 секунд` относится к выпуску трёх CSV.

Не указывать число запусков, offline-статус или производительность без измерений. Не менять основные входные данные, пороги, веса или алгоритмы только ради зелёной проверки.

## Ограничения проверки

Контрактные тесты проверяют соответствие документированным правилам и форматам. Они не измеряют AML accuracy, precision/recall или вероятность нарушения: размеченного ground truth нет. Официальные контрольные размеры и оборот берутся из [SPEC §2](SPEC.md#2-вход-и-валидация); синтетический граф не заменяет полный приёмочный запуск.
